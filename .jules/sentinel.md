## 2026-03-31 - Redactor Secret Leakage in JSON and Structured Payloads
**Vulnerability:** `Redactor.TOKEN_PATTERN` only matched unquoted keyword-value pairs (e.g. `password: 12345`), leaving quoted JSON properties (`"password": "secret"`, `"api_key": "sk-..."`) and multi-word quoted secrets unredacted. In an AI copilot where user commands, tool execution arguments, and audit logs frequently serialize data as JSON, secrets in JSON payloads leaked directly into Room DB (`CommandRecordEntity`, `AuditEventEntity`) and debug logs.
**Learning:** Regex-based credential sanitizers designed for CLI or simple key-value pairs (`key: value`) miss structured serialized data (JSON/YAML) because of quotes wrapping keys and values, as well as space separation within quoted strings.
**Prevention:** Support optional single/double/backtick quote wrappers around credential keywords and values (`(?:token|secret|key|password|bearer|api_key|access_token|refresh_token|private_key)`), matching quoted strings (`"[^"]*"` / `'[^']*'`) in addition to non-whitespace tokens.
